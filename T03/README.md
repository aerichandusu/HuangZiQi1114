# 招聘职位画像可视化系统「职镜 JobLens」· 设计说明文档

> 任务：1.3【设计方向必做】可视化系统设计
> 交付物：本说明文档 + 同目录 `design.png`（完整设计图）
> 数据说明：本设计不需要真实数据，设计图中使用**模拟数据**（30,130 条招聘信息），字段遵循题目给定的 JobId / JobName / Province / City / Education / Experience / Salary / CompanyType。

## 1. 系统定位与目标用户

**一句话定位**：把分散的招聘信息聚合成可比较的"职位画像"，帮助用户在 30 秒内回答四个问题——**投哪个城市、投什么岗位、能拿多少钱、需要什么条件**。

**主视角：求职者**（应届生、1-3 年经验的转岗者、异地求职者）。他们最典型的困境不是"没有岗位"，而是"信息过载且不可比"：同名岗位在不同城市、不同行业的薪资与门槛差异极大，逐条阅读几百条招聘信息既低效也难以形成判断。

**副视角：企业 HR**（右上角"求职者 / 企业 HR"切换）。切换后同一套数据改用竞争视角解读：以本地同岗位的薪酬分位判断自身定价的竞争力，用学历与经验门槛分布评估人才池规模，避免岗位长期招不满。

## 2. 数据说明与预处理

| 字段 | 处理方式 |
| --- | --- |
| `Salary`（如 `{8000 - 15000, 14薪}`） | 拆为月薪下限、上限、发薪月数；**年薪估算 = 月薪中位数 × 发薪月数**；同时统计 15 薪以上岗位占比、月薪 ≥ 30k 的占比等派生指标 |
| `Province` / `City` | 城市保留原名用于排行；省份归并为**华东 / 华南 / 华北 / 华中 / 西南 / 其他**区域，用于区域分布 |
| `Education` | 映射为序数（不限 < 大专 < 本科 < 硕士 < 博士），既能做分布，也能做矩阵的行 |
| `Experience` | 映射为序数（应届 / 1-3 年 / 3-5 年 / 5-10 年 / 10 年以上），用于薪资分层与热力图列 |
| `CompanyType` | 作为行业维度，用于矩形树图与筛选 |
| 派生指标 | 职位画像的 6 个维度统一归一化到 0-100（薪资水平、城市集中度、行业热度、岗位供给量、学历门槛、经验门槛），保证雷达图跨维度可比 |

## 3. 用户问题 → 分析任务 → 视图

| 用户问题 | 分析任务 | 对应视图 |
| --- | --- | --- |
| 岗位都分布在哪些城市？ | 空间分布比较 | ① 城市分布（地图 + 气泡 + 排行 + 区域占比） |
| 薪酬大概什么水平？和经验的关系？ | 分布与区间比较 | ② 薪酬待遇（按经验分层的区间条） |
| 这个岗位整体是什么"画像"？和别的岗位差在哪？ | 多维特征聚合与对比 | ③ 职位画像雷达图 |
| 岗位主要来自哪些行业？ | 类别构成 | ④ 行业分布矩形树图 |
| 学历和经验门槛高不高？ | 有序类别交叉分布 | ⑤ 学历 × 经验热力图 |
| 所以我到底该怎么选？ | 结论提炼与建议 | ⑥ 自动洞察与决策建议 |
| 具体有哪些岗位可以投？ | 明细查阅与下钻 | ⑦ 招聘信息明细表 + 职位详情卡 |

## 4. 系统总体布局与视觉规范

自上而下分为六层，符合"先筛选、再看全局、再看维度、最后看明细"的分析节奏：

1. **顶栏**：系统名 + 视角切换（求职者 / 企业 HR）+ 数据范围说明。
2. **筛选条**：岗位、城市、学历、经验、行业五个下拉 + 月薪区间滑块 + 应用/重置，放在最上方是因为它同时作用于所有视图。
3. **KPI 行**：岗位总量、平均月薪、岗位最集中城市、最热行业，先用四个数字给出全局印象。
4. **主视觉层（① ② ③）**：城市分布（占 6/12 宽度，信息量最大）、薪酬待遇、职位画像。
5. **维度层（④ ⑤ ⑥）**：行业分布、学历×经验矩阵、自动洞察与决策建议。
6. **明细层（⑦）** 与底部的**交互设计说明条**。

**视觉规范**：主色深蓝 `#1f4e79`（品牌与结构）、强调色橙 `#e2701e`（关注与高亮）、对比色青绿 `#2f8f83`（画像与门槛）；地图使用单色渐进色阶表示岗位密度，避免彩虹色带来的误读；所有数值使用等宽数字，保证纵向对齐可比。

## 5. 各视图设计说明

### ① 城市分布｜岗位偏好城市

- **编码**：省级色块深浅 ∝ 岗位数量（渐进色阶 + 图例）；重点城市用**气泡**叠加，半径 ∝ 岗位数；右侧为 Top 8 城市排行条；底部为区域占比标签；再下方是"平均月薪 · 前五城"的横向条。
- **为什么这样设计**：地图擅长回答"在哪里"，但**面积会带来误读**（西部省份面积大但岗位少），因此把它与排行条并置——地图给空间直觉，排行条给精确比较。岗位数量与平均月薪分开呈现，避免把"岗位多"误读成"薪资高"。
- **交互**：点击省份或城市，其余视图同步过滤。

### ② 薪酬待遇｜按经验分层

- **编码**：每一档经验一条水平区间条（月薪下沿到上沿），圆点标出中位数；底部为月薪刻度（6k-56k）。
- **为什么这样设计**：面向非专业用户，区间条比箱线图直观；把经验作为分组变量，是因为它是对月薪解释力最强的单一变量，且求职者能直接对照自身处境。右侧补充"薪资带宽 1:6.7""15 薪以上占比 31.5%"等派生指标，回答"上限能到哪、福利结构如何"。

### ③ 职位画像｜多维对比

- **编码**：6 个维度（薪资水平、城市集中度、行业热度、岗位供给量、学历门槛、经验门槛）呈放射状，每个岗位一个多边形，最多叠加 3 个岗位。
- **为什么这样设计**：单选题给答案，画像题给"形状"。当用户同时考虑"软件工程师 vs 产品经理"时，两条折线的差异（前者行业热度与供给量更高、后者学历门槛更高）比两列数字更容易记住。

### ④ 行业分布｜岗位来源结构

- **编码**：矩形树图，面积 ∝ 岗位数，色彩由深到浅表示占比递减。
- **为什么这样设计**：行业是类别变量且数量不多，树图能在一屏内同时表达"有哪些行业"和"谁占主导"；配合"信息技术服务 + 互联网合计 51.7%"的注释，直接把构成结论说出来。

### ⑤ 学历 × 经验｜门槛分布

- **编码**：4×5 热力矩阵，行=学历、列=经验，单元格数值为岗位数，色深 ∝ 数量。
- **为什么这样设计**：学历与经验是求职的"硬门槛"，两者交叉才能回答"我这样的背景有多少机会"。热力图让空缺区（如"博士 × 应届"）和主力区（"本科 × 1-3 年"）一眼可见。

### ⑥ 自动洞察与决策建议

- **编码**：三条自然语言洞察，每条包含"现象（含数字）+ 决策建议"。
- **为什么这样设计**：可视化的终点是决策。把跨视图计算出的结论写成句子，让不擅长读图表的用户也能直接使用；关键数字加粗，避免"看了图但不知道所以然"。

### ⑦ 招聘信息明细表

- **编码**：职位名称、行业、城市、学历、经验、月薪区间、年薪估算、标签（高薪 / 紧缺 / 应届友好 / 门槛适中）。
- **交互**：点击任意一行展开职位详情卡（职位描述、公司信息、相似岗位推荐），实现从"聚合视图"到"单条信息"的下钻闭环。

## 6. 交互与联动设计

| 编号 | 交互 | 目的 |
| --- | --- | --- |
| 1 | 顶部筛选与全屏视图联动，实时重算 | 让"我的条件"贯穿始终，避免多视图口径不一致 |
| 2 | 点击地图省份或城市排行，其余视图同步过滤 | 把空间直觉转化为可继续探索的子集 |
| 3 | 悬停任意图元显示数值、样本量与置信区间 | 支撑"看到的结论是否可信"的判断 |
| 4 | 点击明细行展开职位详情卡与相似岗位 | 从聚合结论回到可投递的具体岗位 |
| 5 | 雷达图支持最多三个岗位叠加对比 | 支持"多选项权衡"这一真实决策场景 |
| 6 | 求职者 / 企业 HR 视角切换 | 同一份数据服务两类决策者 |

## 8. 设计取舍

1. **地图 + 排行并置，而不是只放地图**：避免面积错觉，兼顾空间直觉与精确比较。
2. **薪资用区间条而非箱线图**：目标用户包含非专业读者，区间条（下沿-上沿-中位数）理解成本更低；同时把"年薪估算"放进明细表，回应薪资结构的真实口径（发薪月数）。
3. **雷达图使用 0-100 归一化并限定最多三个岗位**：解决不同量纲不可比的问题，也避免线条过多导致不可读。
4. **洞察写成自然语言**：考核强调"用户能获得什么洞察、如何帮助决策"，因此把结论显式写进界面，而不是留给用户从图形里自行推断。
5. **模拟数据口径一致**：所有派生比例都基于同一份模拟数据（30,130 条）计算，保证设计图内部自洽。

## 9. 后续可扩展方向

- 增加近 12 个月的岗位量与薪资中位数趋势，识别需求与薪酬的周期性。
- 增加"公司维度"视图（规模、融资阶段、岗位发布活跃度），支撑"投什么公司"的判断。
- 引入简历匹配度：结合用户的教育背景与经验，实时计算各视图中的匹配岗位占比。
- 支持多岗位对比报告导出，便于横向比较后做出最终决策。
