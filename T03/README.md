## 摘要

**职镜 JobLens** 是一套面向**求职者**（并兼顾**企业 HR**）的招聘职位画像分析系统。它把分散的招聘信息聚合成可比较的"职位画像"，用一屏回答四个问题——**投哪个城市、投哪个岗位、能拿多少钱、需要什么条件**，并进一步通过 **MBTI 适配排行**与**个性关键词匹配**回答"我适合这个岗位吗"。

系统由九个协同板块组成：城市分布、薪酬待遇、职位画像、行业分布、学历×经验门槛、自动洞察与决策建议、招聘信息明细、MBTI 匹配排行、个性关键词分析。切换岗位时只变数据、不变结构，因此用户始终在同一维度上做比较；每条洞察都写成"现象 + 决策建议"，让可视化结果可以直接转化为行动。

## 一、系统目的

### 1.1 要解决的问题

求职者面对招聘信息时，真正的困难不是"没有岗位"，而是**"信息过载且不可比"**：同一个职位名称在不同城市、不同行业的薪资区间和门槛要求差异极大，逐条阅读几百条招聘信息既低效，也难以形成可以据以行动的判断。具体表现为三个"看不清"：

1. **看不清岗位在哪里**——岗位在哪些城市密集、哪些城市只是零星出现；
2. **看不清能拿多少**——薪资中位数与区间带宽是多少，和经验是什么关系；
3. **看不清自己够不够格**——学历与经验门槛分布如何，自己的背景处在什么位置；更进一步，性格特质与岗位要求是否匹配。

企业 HR 侧则存在第四个"看不清"：**不知道自己的岗位要求与薪酬在市场上处于什么分位**，容易招不到人或招错人——本系统通过右上角的视角切换，用同一份数据服务这一类判断。

### 1.2 目标用户与使用场景

| 角色 | 典型场景 | 想得到的结论 |
| --- | --- | --- |
| 求职者（主视角） | 应届毕业选择投递方向、1-3 年经验者考虑跳槽、异地求职者判断城市 | 投哪个城市、投哪个岗位、能拿多少钱、需要补什么条件 |
| 企业 HR（副视角） | 发布岗位前对标市场、复盘某岗位长期招不满的原因 | 我的薪酬与门槛在同岗位里处于什么位置 |

### 1.3 设计目标

1. **30 秒内回答四个问题**：投哪个城市、投哪个岗位、能拿多少钱、需要什么条件。
2. **一屏内完成"筛选 → 比较 → 匹配"闭环**：不必在多个系统之间来回切换。
3. **把结论直接写成可行性建议**：不只呈现图表，而是把跨视图计算出的结论写成"现象 + 决策建议"。

## 二、基本设计

### 2.1 数据与预处理

数据字段沿用岗位招聘信息的标准结构，并在进入可视化前做统一加工：

| 原始字段 | 含义 | 处理方式 |
| --- | --- | --- |
| `JobId` | 每条招聘信息的唯一索引 | 作为唯一键，去重与计数的基础 |
| `JobName` | 职位名称 | 归并为 5 类示例岗位：软件工程师、产品经理、人力资源专员、财务分析师、市场营销专员 |
| `Province` / `City` | 企业所在省份 / 城市 | 城市保留原名用于排行；省份归并为华东 / 华南 / 华北 / 华中 / 西南 / 其他，用于区域占比 |
| `Education` | 学历要求 | 映射为序数（不限 < 大专 < 本科 < 硕士 < 博士），既做分布也做矩阵的行 |
| `Experience` | 经验要求 | 映射为序数（应届 / 1-3 年 / 3-5 年 / 5-10 年 / 10 年以上），用于薪资分层与热力图列 |
| `Salary` | 形如 `{8000 - 15000, 14薪}` | 拆为月薪下限、上限、发薪月数；派生**年薪估算 = 月薪中位数 × 发薪月数**；并统计 15 薪以上占比、月薪 ≥ 30k 占比等指标 |
| `CompanyType` | 行业 | 作为行业维度，用于矩形树图与筛选 |
| 派生指标 | — | 职位画像的 6 个维度统一归一化到 0-100（薪资水平、城市集中度、行业热度、岗位供给量、学历门槛、经验门槛），保证雷达图跨维度可比 |

> **数据说明**：设计图与原型的数值均为**模拟数据**（共 30,130 条招聘信息），五个岗位合计与总量一致、各视图口径互相自洽（例如"五城占 24.1%""3-5 年薪资是应届的 1.9 倍"都由同一份数据算出）。

### 2.2 信息架构

界面自上而下分六层，对应"先限定范围 → 再看全局 → 再看维度 → 最后看明细"的分析节奏：

```
顶栏（品牌 + 视角切换 + 数据范围）
  └─ 筛选条（岗位 / 城市 / 学历 / 经验 / 行业 / 月薪区间）
       └─ 快速切换岗位（5 个岗位标签，一键换数据）
            └─ KPI 行（岗位总量 / 平均月薪 / 最集中城市 / 最热行业）
                 ├─ 主视觉层：① 城市分布  ② 薪酬待遇  ③ 职位画像
                 ├─ 维度层：  ④ 行业分布  ⑤ 学历×经验  ⑥ 自动洞察与决策建议
                 ├─ 明细层：  ⑦ 招聘信息明细
                 └─ 匹配层：  ⑧ MBTI匹配排行  ⑨ 个性关键词分析
```

九个板块各自回答一个问题，并用不同的图表承担不同的任务：

| 板块 | 回答的问题 | 主要可视化 | 关键交互 |
| --- | --- | --- | --- |
| ① 城市分布 | 岗位在哪里 | 省级分级色块地图 + 城市气泡 + Top8 排行条 + 区域占比 + 城市平均月薪条 | 切换岗位时地图色阶与气泡同步变化；悬停省份显示岗位数 |
| ② 薪酬待遇 | 能拿多少钱 | 按经验分层的月薪区间条（区间 + 中位数点）+ 派生指标 | 悬停查看中位数；切换岗位重算区间 |
| ③ 职位画像 | 这个岗位是什么"形状" | 六维雷达图（当前岗位 vs 全岗位平均） | 切换岗位对比两条多边形 |
| ④ 行业分布 | 岗位来自哪些行业 | 矩形树图（面积 ∝ 岗位数） | 悬停查看占比 |
| ⑤ 学历 × 经验 | 门槛高不高 | 4×5 热力矩阵（行=学历，列=经验） | 悬停查看岗位数；颜色越深需求越集中 |
| ⑥ 自动洞察与决策建议 | 所以我该怎么选 | 自然语言结论卡（现象 + 决策建议） | 随岗位实时刷新 |
| ⑦ 招聘信息明细 | 具体有哪些岗位 | 表格（职位 / 行业 / 城市 / 学历 / 经验 / 月薪 / 年薪估算 / 标签） | 点击行查看职位详情卡（此为后续优化项） |
| ⑧ MBTI匹配排行 | 我的性格适合吗 | 三档排行卡（TOP·最适合 / 2nd·比较适合 / 3rd·可以考虑），每档含类型组、别称与 MBTI 代码 | 随岗位切换更新排行 |
| ⑨ 个性关键词分析 | 我适合哪些岗位 | 7 维度 40 个关键词词块 + 拖拽分析栏 + 匹配度排行条 | 拖拽或点击选词、点"点击分析"出结果、点 × 移除 |

### 2.3 关键设计取舍

1. **地图与排行并置，而不是只放地图**：地图擅长回答"在哪里"，但面积会带来误读（西部省份面积大而岗位少），因此并置一个排行条——地图给空间直觉，排行条给精确比较。
2. **薪资用区间条而非箱线图**：目标用户包含非专业读者，区间条（下沿-上沿-中位数）理解成本更低；同时把"年薪估算"放进明细表，回应薪资结构的真实口径（发薪月数）。
3. **雷达图使用 0-100 归一化**：解决不同量纲不可比的问题，并用"全岗位平均"作为参照系，让"高不高"变成"比平均高多少"。
4. **洞察写成自然语言**：可视化的终点是决策，因此把跨视图计算出的结论直接写成句子，避免"看了图但不知道所以然"。
5. **切换岗位时只变数据、不变结构**：布局、面板数量、坐标轴范围、颜色语义全部保持不变——只有同一维度上比较，用户才能在不同岗位之间做出判断。
6. **门槛矩阵的联合分布按边际占比近似合成**：在只有学历、经验两个边际分布的情况下，用独立近似生成交叉分布，已在界面上注明为模拟数据。

## 三、使用说明

### 3.1 快速上手（五步）

1. **选身份**：右上角选择"求职者视角"或"企业 HR 视角"（当前原型中该切换为演示入口）。
2. **选岗位**：点击"快速切换岗位"里的任一标签——整页九个板块会同时刷新为该岗位的数据。
3. **看全局**：先看 KPI 行的四个数字（岗位总量、平均月薪、最集中城市、最热行业），建立第一印象。
4. **看维度**：依次看 ①-⑤，回答"在哪里、多少钱、什么形状、哪些行业、门槛多高"。
5. **要结论**：直接读 ⑥ 的三条"现象 + 决策建议"；想了解自己适合什么，用 ⑧ 的 MBTI 排行和 ⑨ 的关键词分析。

### 3.2 各板块怎么看

| 板块 | 操作 | 你会得到 |
| --- | --- | --- |
| ① 城市分布 | 看地图色深找密集区，再看右侧排行榜确认具体名次与数量，最后看底部"平均月薪·前五城" | 该岗位"必须去的城市"是哪几个；岗位多不等于薪资高 |
| ② 薪酬待遇 | 从上到下对照自己所在的经验档，看区间条的长短与中位数点 | 自己这一档的薪资预期区间与上限；跳档之后的涨幅空间 |
| ③ 职位画像 | 看当前岗位多边形相对"全岗位平均"凸出或凹陷的方向 | 这个岗位的优势维度（如行业热度）与门槛维度（如学历要求） |
| ④ 行业分布 | 看面积最大的两个行业 | 行业集中度：投递时该优先选哪个行业 |
| ⑤ 学历 × 经验 | 找到自己背景所在的行与列，看该格的数值与色深 | "我这样的背景有多少机会"；例如"本科 × 1-3 年"是否为最大需求格 |
| ⑥ 洞察建议 | 直接阅读 | 三条可直接执行的建议 |
| ⑦ 明细表 | 浏览前 5 条示例，看月薪区间与年薪估算 | 从聚合结论落到具体的岗位样本 |
| ⑧ MBTI 排行 | 看 TOP 档的类型组与 MBTI 代码 | 该岗位更常出现的性格倾向 |
| ⑨ 关键词分析 | 选 3-5 个关键词 → 点"点击分析" | 5 个岗位的匹配度排行与推荐理由 |

### 3.3 个性关键词分析：操作细节

**操作方式**：从下方 7 个维度的词块中，**拖拽**到上方虚线分析栏；也可以**直接点击**词块添加（拖拽为主、点击为辅，照顾不便拖拽的用户）。已选词会显示为深色标签，点标签上的 `×` 可以移除，**最多同时选择 5 个**，超过会提示。

**七个维度与关键词**：

| 维度 | 关键词 |
| --- | --- |
| 思维方式 | 逻辑分析、数据敏感、结构化思维、创意发散、注重细节、宏观视野 |
| 社交风格 | 外向健谈、内向沉稳、善于倾听、团队协作、独立作业、共情力强 |
| 做事方式 | 计划性强、随机应变、执行力强、完美主义、多线程处理、专注深耕 |
| 情绪与韧性 | 抗压能力强、情绪稳定、耐心持久、乐观积极、冷静理性 |
| 内在驱动 | 好奇心强、追求成就、喜欢挑战、追求稳定、热爱自由、利他助人 |
| 领导与影响 | 领导力、决断力、说服表达、资源协调、竞争意识 |
| 兴趣倾向 | 技术钻研、审美设计、商业洞察、语言表达、动手操作、户外走动 |

**分析怎么算的**：每个岗位都有一组"强关联关键词"与一组"反向关键词"。命中强关联词 **+2 分**，命中反向词 **−1 分**，再按已选数量归一化为 0-100 的匹配度（上限 98%，避免"满分"造成的绝对化解读）。未列入该岗位的词既不加分也不减分。

**读结果的方式**：结果区显示匹配度前三名的岗位与百分比，并给出理由，例如——选「创意发散 + 外向健谈 + 说服表达」时，市场营销专员匹配度最高，因为这三个词正是该岗位的核心要求；而选「逻辑分析 + 注重细节 + 专注深耕」时，软件工程师会排在第一位。

### 3.4 MBTI 匹配排行：怎么读

排行按"类型组 + 别称 + 两个 MBTI 代码"给出三档：TOP·最适合、2nd·比较适合、3rd·可以考虑。类型组遵循 MBTI 的四大分组：

| 类型组 | 包含类型 | 常见倾向 |
| --- | --- | --- |
| SJ 守护者 | ISTJ / ISFJ / ESTJ / ESFJ | 务实、守序、重细节与流程 |
| SP 探索者 | ISTP / ISFP / ESTP / ESFP | 灵活、擅长临场应变与动手 |
| NT 分析家 | INTJ / INTP / ENTJ / ENTP | 逻辑驱动、擅长建模与推演 |
| NF 外交家 | INFJ / INFP / ENFJ / ENFP | 共情、擅长协调与影响他人 |

**必须注意**：模块标题下方已经写明"适合不是必然，人格类型只是参考"。MBTI 说明的是**倾向**而不是能力边界，因此系统把它放在"参考层"，与基于岗位要求的关键词匹配结果并列展示、互相印证，而不是当作录取标准。

### 3.5 常见问题

- **匹配度为什么没有 100%？** 上限设为 98%：性格与岗位要求之间不存在"完全吻合"，留出空间避免绝对化的判断。
- **为什么只显示前 3 个岗位？** 排行榜过长会稀释结论；前 3 名足以支撑"主投 + 备选"的决策，完整名单可在明细表中继续查阅。
- **一个关键词都不选能分析吗？** 不能，会提示"先选 3-5 个关键词"。选 3-5 个词的区分度最好：太少结论不稳，太多会相互抵消。
- **切换岗位会清空我选的关键词吗？** 不会。关键词是"关于你自己"的输入，与岗位无关；切换岗位后匹配度排行会自动重算。

## 六、局限与后续优化

**当前局限**：

1. 数据为模拟数据，未接入真实招聘平台；门槛矩阵的交叉分布按边际占比近似合成。
2. 关键词与岗位的匹配规则由人工设定分析规则，尚未用真实招聘要求训练。
3. MBTI 排行基于类型组的普遍倾向，不构成个体能力判断。
4. 明细表的"职位详情卡"与原型的"企业 HR 视角"目前为演示入口，未实现完整逻辑。

**后续可优化方向**：

1. 增加近 12 个月的趋势视图，识别岗位量与薪资中位数的周期性；
2. 增加"公司维度"（规模、融资阶段、发布活跃度），支撑"投什么公司"的判断；
3. 引入简历匹配度：结合用户真实背景进行分析，实时计算各视图中的匹配岗位占比；
4. 让关键词权重可从真实招聘文本中学习（如按岗位描述中出现的频次与位置赋权）；
5. 支持多岗位对比报告的导出，便于横向比较后做出最终决策。
