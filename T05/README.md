# AI 工具使用情况与使用感受

> 对应任务 1.5：说明完成本次笔试时使用了哪些 AI 工具、它们分别解决了哪些具体问题，以及使用体验与感受。

## 一、我用了哪些 AI 工具

**主力工具是 Codex（基于 GPT-5 的编程与研究助手）。** 从 10 月 11 日到 10 月 16 日，笔试里几乎所有环节都有它的参与：读文献、写综述、生成设计图、写交互原型、排查 Git 命令、把 Word 转成 Markdown。除了它之外，我没有使用其他 AI 工具来生成内容。

| 工具 | 用在哪 | 具体解决了什么问题 |
| --- | --- | --- |
| **Codex**（GPT-5） | T02 文献研究 | 逐篇精读英文论文，把关键信息提炼成统一框架（论文信息 / 解决的问题 / 方法与可视化设计 / 主要贡献与创新点 / 评估与局限）；对难读的图表和术语给出解释；帮我核对数字与出处 |
| | T02 选题与找文献 | 用它检索高水平期刊上的候选文献，并按贴合度分层推荐（最后据此把 TED Talks 与 M²Lens 换进了核心五篇） |

## 二、AI 在每道题里具体帮了什么

### 1.1 GitHub 与 Markdown 基础

这部分我原本只有模糊概念。AI 帮我把"要建仓库"拆成了可执行的一步一步：先鉴定环境（发现机器上其实没装 Git，也没有配置提交身份），再给出克隆、建目录、提交、推送的完整命令，并且每次命令后都说明"预期看到什么输出、不对时怎么办"。它还把考核要求的目录结构提前搭好（含 `.gitkeep` 占位，避免空文件夹在 GitHub 上消失），我只需要照着做。后来遇到"远端和本地都有提交"的冲突，它先抓取远端、发现是我在网页上改过 README，于是做了合并而不是覆盖。

### 1.2 研究总结

这是 AI 帮我最多的一项，但也是我参与判断最多的一项。

**它做了三件事**：一是精读。五篇核心文献加起来 59 页（Anchorage 15 页、VisTellAR 13 页、微课框架 6 页、TED Talks 14 页、M²Lens 11 页），还有几篇延伸文献，全部由它先读一遍再提炼。二是给出可复用的框架，让五篇的写法一致，我不用自己每次重新组织。三是在我卡住时提供判断依据——比如我问"这个方向还有哪些高水平期刊的文献"，它去检索并逐条核对了作者、卷期页码、DOI 和被引量，还告诉我一个有用的结论：这类工作几乎都在 IEEE TVCG 上，TCSVT、TMM 上的多为算法论文。

**实际用起来的效果**：M²Lens 那篇 PDF 的正文是矢量轮廓、没有文字层，常规提取只能拿到页码，AI 改用逐页渲染成图片来读，最后依然给出了完整的三层解释框架。这类"工具层面的障碍"，它处理得比我快得多。

### 1.3 可视化系统设计

我的设计想法是有的，但不会用 Figma 从零画一套界面。AI 的做法是：先把需求拆成"用户要回答哪些问题 → 对应哪些视图 → 每个视图用什么编码"，形成信息架构；再用 HTML/CSS/SVG 把整页画出来（1600×1880 的画板，含地图、雷达图、矩形树图、热力矩阵），导出成高清 PNG；最后额外生成一份矢量 SVG，让我拖进 Figma 就能当主画板继续改。这个顺序对我很友好——**我不是从空白画布开始，而是在一个能跑的设计上做判断和修改**。

后来我提出想加"个性关键词分析"（拖关键词进行分析）和 MBTI 匹配排行，它帮我把关键词库按七个维度组织起来（40 个词），并把"关键词到岗位"的匹配规则写清楚（命中强关联词 +2 分、反向词 −1 分，上限 98%），这样界面上的百分比才有依据，而不是随手编的数字。

### 1.4 前端方向的可视化设计实现（未做）

这道题对应的是"雷达图里嵌地平线图"的增强雷达图，属于前端方向。我本次选择的是设计方向，没有写代码实现，只和 AI 讨论并记录了对题目的理解与设计思路（雷达图负责表达各维度的均值，地平线图负责表达每个维度内部的分布，两者通过把地平线图画进雷达图的扇形区域来组合），思路记在 `T04/README.md`。这也是 AI 帮到我的一次：即使我暂时做不出实现，它也能把"这个图到底想解决什么问题"讲清楚，让我至少能理解题目。

### 文档与收尾

最后把 Word 里的五篇综述转成 Markdown 时，它统一了标题层级、把我写错序号的章节理顺（原来有一节从"一"跳到"三"）、把两个 Word 表格转成 Markdown 表格，还补齐了参考文献列表。我原来那三条从论文里机翻过来的贡献描述（"……时的问题表征"这类不通顺的句子），也请它改成了通顺的中文。

## 三、AI 帮得最多的地方，和它最容易出错的地方

**帮得最多的三处**：跨语言文献的精读与结构化；把设计想法直接变成可运行的代码或可编辑的矢量文件；以及各种工具链的排错（Git、PowerShell、PDF 解析）。

**它也确实会出错**，我遇到过的几种：

- 它给我写的一个辅助脚本在 Windows PowerShell 下直接报语法错，原因是文件被存成不带 BOM 的 UTF-8，中文提示被解码错了。改成全英文提示后才跑通。
- 生成的界面里出过一次样式冲突：`.top` 这个类名同时用在了顶栏和"排行榜前两名"上，结果排名前两行被染成了渐变块。这种问题肉眼看渲染图才能发现，AI 自己不会主动察觉。
- 它第一次拿到的省级地图数据是压缩编码过的（坐标是字符串不是数组），需要先解码才能用。
- 有一篇论文的 PDF 没有文字层，常规解析只返回了页码，它一开始的提取结果几乎是空的。

这几件事让我形成一个习惯：**AI 给的东西，必须自己跑一遍、看一眼、对一遍。**

## 四、我是怎么验证 AI 输出的

1. **文献部分回到原文核对**。它总结里的数字（比如 21.8% 的提速、封闭姿态占 35%、用户研究 16 人、所有任务 91 秒内完成）我都会翻到对应段落确认；只要有一次对不上，我就会把整篇重新看一遍。
2. **代码和原型亲自运行**。交互原型我在浏览器里点过每一处：切换五个岗位看九个板块是否都跟着变、拖关键词看匹配度是否正确重算、点 × 看能不能移除。
3. **设计图逐块检查**。设计图导出后我会看有没有文字被裁掉、色块有没有压住文字，前面提到的样式冲突就是这么发现的。
4. **术语和结论按自己的理解复述一遍**。凡是我复述不出来的地方，说明我还没真懂，就会回去补读。

## 五、使用感受与反思

**第一，AI 把我从"写"推到了"审"。** 以前做文献综述，大量时间花在查词、翻译、组织句子上；现在这些由 AI 出初稿，我的时间主要用来判断"它说的对不对、是不是重点、要不要保留"。这种转变我觉得是好事——判断力才是真正属于我的部分——但也带来一个新的风险：如果我不核对，就只是在搬运。所以我给自己定了上面那套验证习惯。

**第二，它显著降低了"工具门槛"，但没有降低"思考门槛"。** 我不会 Figma、不会写前端、Git 也只是听说过，这些障碍几乎都被抹平了；但"这个系统该解决谁的问题、九个板块哪些是必要的、洞察怎么写才站得住"这些，AI 只能给我选项，拍板的是我。比如它一开始建议的五篇文献里有篇偏算法、不算可视分析，我按它的分析把它换成了更贴合方向的两篇，这个取舍得我自己扛。

**第三，它对"诚实"这件事是有帮助的。** 我请它写总结时特意要求"局限"部分不能省略，因此每篇都保留了作者自陈的局限，以及我们额外看出来的问题（例如某篇只有一个案例、没有用户研究）。写综述最怕把论文说得完美无缺，这一点 AI 反而提醒了我。

**第四，最大的体会是"我得更清楚自己要什么"。** 这几天的推进里，凡是我能把需求说清楚的（比如"我要能选岗位、能拖关键词、还要看匹配度"），AI 一次就能给到比较接近的东西；凡是我说得含糊的（比如"再好看一点"），返工就多。这大概就是和 AI 协作最核心的能力。

最后一句实话：AI 让我在六天里做完了一个人可能要两三周才能完成的量，但它不能替我在答辩时说清楚"为什么这么设计"。所以文档我都是自己读过、改过措辞之后再提交的——**能用 AI，也要能对结果负责。**
