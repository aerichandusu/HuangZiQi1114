# AI 工具使用情况与使用感受

> 对应任务 1.5：说明完成本次笔试时使用了哪些 AI 工具、它们分别解决了哪些具体问题，以及使用体验与感受。

## 一、AI 工具概括

**主要工具是 Codex以及figma自带的AI。** 从 10 月 11 日到 10 月 16 日，笔试里几乎所有环节都有它的参与：读文献、写综述、生成设计图、写交互原型、排查 Git 命令、把 Word 转成 Markdown。除此之外，我没有使用其他 AI 工具来生成内容。

| 工具 | 用在哪 | 具体解决了什么问题 |
| --- | --- | --- |
| **Codex**（GPT-5） | T02 文献研究 | 逐篇精读英文论文，把关键信息提炼成统一框架（论文信息 / 解决的问题 / 方法与可视化设计 / 主要贡献与创新点 / 评估与局限）；对难读的图表和术语给出解释；帮我核对数字与出处 |
| | T02 选题与找文献 | 用它检索高水平期刊上的候选文献，并按贴合度分层推荐选择更符合选题的文献 |
| | T03 可视化系统设计 | 从给出的需求和设计想法出发一起定信息架构与九个板块，并给出可导入 Figma 的矢量元素文件 |

## 二、AI 具体使用情况

### 1.1 GitHub 与 Markdown 基础

这部分我原本只有使用github的基础并且不多，在AI的指令下安装了git并把对应代码写进去，从而成功按照目录要求搭建了自己的仓库。

### 1.2 研究总结

这是 AI 帮我最多的一项，但也是我参与判断最多的一项。

**它做了三件事**：一是精读。五篇核心文献加起来 59 页（Anchorage 15 页、VisTellAR 13 页、微课框架 6 页、TED Talks 14 页、M²Lens 11 页），还有几篇延伸文献，全部由它先读一遍再提炼。二是给出可复用的框架，让五篇的写法一致，我不用自己每次重新组织。三是向我解释文献中使用的专业术语以及名词。当然我都是先把摘要和每个标题自己看了之后才让AI帮我分析难以看懂的主干部分，确实我的专业能力有限，所以很多东西还是要借助AI才能看懂。


### 1.3 可视化系统设计

我的设计想法是有的，但是本人最近确实很忙碌（sorry），如果从0开始手搓矢量图的话我就会耗费大量的精力。所以我先让AI把需求拆成"用户要回答哪些问题 → 对应哪些视图 → 每个视图用什么方式呈现"，形成信息架构；再让AI把地图、雷达图、矩形树图、热力矩阵这些矢量图发给我，结合AI的意见我自己对这些视图进行编排；最后额外生成一份矢量 SVG，让我拖进 Figma 就能当主画板继续改。

后来我觉得现在的职业分析系统肯定是比我做得更好的，所以我在思考怎么让我的设计更有新意，我想到现在很多人都会通过自己的MBTI人格特点进行职业规划，加上我一直觉得要选择一份适合自己性格的职业，所以我提出想加"个性关键词分析"（拖关键词进行分析）和 MBTI 匹配排行，并让AI帮我把关键词库按七个维度组织起来（40 个词），把"关键词到岗位"的匹配规则写清楚（命中强关联词 +2 分、反向词 −1 分，上限 98%），最后我还是想实现个性关键词分析，便让AI帮我做了交互界面。

### 1.4 前端方向的可视化设计实现（未做）

这道题对应的是"雷达图里嵌地平线图"的增强雷达图，属于前端方向。我本次选择的是设计方向，没有写代码实现（主要也是能力有限），只和 AI 讨论并记录了对题目的理解与设计思路（雷达图负责表达各维度的均值，地平线图负责表达每个维度内部的分布，两者通过把地平线图画进雷达图的扇形区域来组合），思路记在 `T04/README.md`。当然我的能力是做不出实现的，不过AI能把"这个图到底想解决什么问题"讲清楚，让我至少能理解题目。

### 文档与收尾

最后把 Word 里的五篇综述转成 Markdown 时，它统一了标题层级、把我写错序号的章节理顺（原来有一节从"一"跳到"三"）、把两个 Word 表格转成 Markdown 表格，还补齐了参考文献列表。我原来那三条从论文里机翻过来的贡献描述（"……时的问题表征"这类不通顺的句子），也请它改成了通顺的中文。

## 三、验证 AI 输出

1. **文献部分回到原文核对**。它总结里的数字（比如 21.8% 的提速、封闭姿态占 35%、用户研究 16 人、所有任务 91 秒内完成）我都会翻到对应段落确认；只要有一次对不上，我就会把整篇重新看一遍。
2. **代码和原型亲自运行**。设计的几种交互都亲自跑了一遍，这一点不得不被AI折服。
3. **术语和结论按自己的理解复述一遍**。凡是我复述不出来的地方，说明我还没真懂，就会回去补读。

## 四、使用感受与反思

**第一，AI 把我从"写"推到了"审"。** 以前做文献综述，大量时间花在查词、翻译、组织句子上；现在这些由 AI 出初稿，我的时间主要用来判断"它说的对不对、是不是重点、要不要保留"。这种转变我觉得是好事——判断力才是真正属于我的部分——但也带来一个新的风险：如果我不核对，就只是在搬运。所以我给自己定了上面那套验证习惯。

**第二，它显著降低了"工具门槛"，但没有降低"思考门槛"。** 我不会 Figma、不会写前端、Git 也只是听说过，这些障碍几乎都被抹平了；但"这个系统该解决谁的问题、九个板块哪些是必要的、洞察怎么写才站得住"这些，AI 只能给我选项，拍板的是我。比如它一开始建议的五篇文献里有篇偏算法、不算可视分析，我按它的分析把它换成了更贴合方向的两篇，这个取舍得我自己扛。

**第三，它对"诚实"这件事是有帮助的。** 我请它写总结时特意要求"局限"部分不能省略，因此每篇都保留了作者自陈的局限，以及我们额外看出来的问题（例如某篇只有一个案例、没有用户研究）。写综述最怕把论文说得完美无缺，这一点 AI 反而提醒了我。

**第四，最大的体会是"我得更清楚自己要什么"。** 这几天的推进里，凡是我能把需求说清楚的（比如"我要能选岗位、能拖关键词、还要看匹配度"），AI 一次就能给到比较接近的东西；凡是我说得含糊的（比如"再好看一点"），返工就多。这大概就是和 AI 协作最核心的能力。

最后一句实话：AI 让我在六天里做完了一个人可能要两三周才能完成的量，但它不能替我在答辩时说清楚"为什么这么设计"。所以文档我都是自己读过、改过措辞之后再提交的——**能用 AI，也要能对结果负责。**
